## Зачем это нужно

В браузере всё общее. Рабочая почта знает о личной, потому что cookie лежат в
одном хранилище. Вход в один сервис тянет за собой профиль в другом.
Разрешение на уведомления, выданное одному сайту, выглядит так же, как у
остальных сорока вкладок. А нужная вкладка теряется среди прочих и закрывается
вместе с браузером.

Alcove разносит это по отдельным приложениям. Каждый сайт получает собственное
окно, профиль, cookie, кэш и разрешения. Два аккаунта одного сервиса живут
рядом и ничего не знают друг о друге. Приложение запускается из меню GNOME,
как любое другое, и не зависит от того, открыт ли браузер.

## Что это даёт

- **Два аккаунта одного сервиса одновременно** — без режима инкогнито и без
  второго браузера.
- **Рабочее отдельно от личного** — сессии не пересекаются в принципе, а не по
  договорённости с собой.
- **Сайт как программа** — своя иконка в меню, своё место в переключателе окон.
- **Разрешения по месту** — камера, микрофон, уведомления и геолокация выдаются
  конкретному сайту, а не браузеру целиком.
- **Данные под контролем** — профиль можно выгрузить в архив, перенести на
  другую машину или удалить вместе с приложением.

## Как устроено

Alcove — приложение GNOME на GTK 4 и libadwaita. Содержимое сайта показывает
встроенный движок, а окно, меню и навигация остаются родными для системы.

| Движок | Роль |
| --- | --- |
| **WebKitGTK** | Родной для GNOME, используется по умолчанию. |
| **Chromium** | Дополнение для сайтов, которым WebKitGTK не хватает. |

Chromium ставится отдельным дополнением Flatpak и **никогда не появляется
сам**. Выбор движка возникает только после установки дополнения, движок не
меняется без подтверждения, а профили и авторизованные сессии двух движков не
смешиваются.

Каждое приложение настраивается отдельно: правила навигации, прокси, работа в
фоне, фильтры содержимого, строка user-agent. Доступ к системе идёт только
через порталы XDG — Alcove не просит широких разрешений Flatpak и не читает
чужие каталоги.

## Установка

Проект на версии 0.1.0, готовых выпусков пока нет. С первым выпуском появится
подписанный репозиторий Flatpak и установка в одну команду; до тех пор
приложение собирается из исходников — порядок описан в
[CONTRIBUTING.md](CONTRIBUTING.md).

## Приватность

Alcove не собирает статистику, не обращается к сторонним службам при запуске и
не отправляет наружу адреса, которые вы открываете.

Единственное необязательное обращение вовне — запрос значка через
[Icon Horse](https://icon.horse/), когда сайт не отдаёт пригодный favicon. Он
происходит **только по нажатию кнопки**, наружу уходит одно лишь имя хоста,
результат сохраняется локально. Без сети провайдер не нужен и не вызывается.

Архивы с данными сайтов шифруются: выгрузить профиль вместе с cookie и
хранилищем без пароля нельзя.

## Чего Alcove не делает

Не поддерживаются и не входят в обещания проекта: DRM и Widevine, расширения
браузера, обход антибот-защиты, закрытые браузерные API. Alcove даёт сайту
отдельное место в системе, а не заменяет браузер.

## Происхождение и лицензия

Alcove — независимое продолжение [Spider](https://github.com/Zaedus/spider) от
коммита `dcf9d1080ce2bbd89c342b4766a94e18aaecf660`. Spider создан главным
образом Zaedus, с участием Cameron Radmore. История Git у Alcove начинается
заново и не содержит исходных коммитов Spider — они остаются в репозитории
Spider, а авторство унаследованного кода записано в [AUTHORS.md](AUTHORS.md).
Прежние авторы не участвуют в Alcove и не выражали его одобрения.

Лицензия — GPL-3.0-only. Подробности: [NOTICE](NOTICE), [AUTHORS.md](AUTHORS.md),
